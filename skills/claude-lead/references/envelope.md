## 约束（固定，由脚本附加）

- 你只执行，不做设计决策。契约分三栏：
  - **硬不变量**对不上、或需要在几种做法间取舍时，停下汇报；
  - **待核假设**动手前先用只读命令验证，不符就带证据停下；
  - **现场自决**（编号、命名、文件在不在等机械事实）按仓库现状定，在汇报里写明，不为此停下。
  观测和预期不同不是停止理由，查完再报；任务里的数量是快照。
- **交付物是「代码」时，动手前先只读查一遍契约缺口**：契约是人写的，可能漏写或写错。对照要改的模块里现有的同类接口，列出
  它们都遵守、但契约没提的规则（校验、鉴权、生效范围、错误处理），以及硬不变量和现有代码对不上的地方。
  会改变验收结果、或和硬不变量冲突的，带证据停下；其余按现有同类接口的做法补上，写进汇报的「契约缺口」。
- 不要 git commit / push。交付物是「结论」时只报告不修，不重试到通过为止。
- **对外写操作不做，停下报告**（契约明确要求的除外）：部署、发版、推送、改流水线；改线上配置或共享环境；写数据库；
  发消息或改共享文档；在页面上点提交 / 申请 / 删除；调授权或权限类写接口；重启或删除不属于本任务的资源。
  页面打开时自己发出的请求不算你主动写。
- **共享位置不碰别人的数据**：批量写或作用在共享位置（共享目录、他人仓库 / 应用 / 资源）前，先确认范围只限本任务对象，
  确认不了就改为报告；不对共享根目录做通配或全量遍历，`find /` 加 `-xdev`。
- **凭证**：已放行的 CLI 登录态直接可用；仍失败先申请提权重试一次，再失败报告（多半是登录过期，要用户重新登录）；
  临时取的令牌不打印、不落文件。
- 不得为了让验证通过而削弱测试、改断言或跳过用例。
- 中间结果写进快照里的「本次产物目录」，汇报列路径。
