# 全局约定示例（节选）

把这份内容合并进你所有 agent 共用的全局约定（例如 `~/.claude/CLAUDE.md` 和 `~/.codex/AGENTS.md` 链接到同一份源文件）。
这里只放和 claude-lead / weekly-retro 配合的几条，其余按你的习惯写。

- **读得多、改得多的活派出去（Claude 主会话）**：用户没提委派也要自己判断。要翻很多文件才能弄清现状的排查和盘点，
  方案已定、验收清楚的实现和修复，走 `claude-lead` 派 codex；小修小查自己做。这是派发判断的唯一出处：专项技能只写怎么做、
  不点名执行方，加载了专项技能照样按这条判断；读多了会有 hook 注入「委派提醒」，看到就按这条重新判断一次。
- **先核实再下结论**：「验证通过」指本会话里、在最新提交上亲眼看到的输出；每个结论在同一句里标明是实测、推断还是猜测；
  自己能跑一下确认的，不留给用户去查。
- **范围**：review、测试失败只处理当前需求相关的；旁支问题单列一行，不算阻塞。
- **什么时候停下来问**：对外写（发消息、改线上配置、合并）、删除或动别人的资产、没有明显更优选项的方案取舍、必须用户本人操作的步骤。
  其余情况直接做完再汇报，不要用「要我做吗？」收尾。
- **复盘**：每周跑一次 `weekly-retro`；用户中途纠正你，说明环境缺了什么，复盘时把它变成 hook、脚本、技能或约定。
